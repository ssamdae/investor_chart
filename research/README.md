# 500억봉 사전 흔적 연구 — 1차 실험

이 폴더는 기존 투자주체 차트의 **운영 코드와 독립**된 읽기 전용 분석입니다. 주식 주문·DB 수정·실행 서비스 변경은 수행하지 않습니다.

## 출처·기준

- 가격/거래대금/개인·외국인·기관: 기존 [`kiwoom_client.py`](../kiwoom_client.py)의 `KiwoomClient.chart()` 호출 (ka10081 + ka10059)
- 거래대금은 ka10059 `acc_trde_prica`(백만원)를 기존 클라이언트가 원화로 변환한 값. 미수신 값은 `NaN`으로 유지
- 시장: `KRX` 기본. 동일 종목/날짜라도 `통합`, `NXT`는 별개 데이터이므로 혼합 비교 금지
- 500억봉 정의: `news_report/filter/signal_filter.py` (2026-10-21 확인) — 거래대금 ≥ 500억원, 고가 ≥ 전일 종가×1.15, 고가 ≥ 저가×1.15, 종가 ≥ 시가×1.09
- 기존 뉴스 리포트 수집기는 종가×거래량으로 거래대금을 추정하지만, **이번 연구에서는 키움의 실제 거래대금**을 기준으로 하므로 과거 이벤트 일치 여부 재검증 필요
- 배당/분할 등 수정주가 이력은 추가 검증 필요. API에서 `adjusted=True` 사용

## 설치 및 실행

기존 `investor_chart` 환경에서 별도 추가 패키지 없이 실행:

```bash
cd /home/ubuntu/apps/investor_chart
source .venv/bin/activate
python -m unittest discover -s tests -p 'test_pre500.py' -v
python -m research.pre500 --code 083450 --start 20250101 --end 20261020 \
    --market KRX --output output/gst_pre500.csv
```

기존 `.env`의 `KIWOOM_APP_KEY`, `KIWOOM_SECRET_KEY`를 재사용합니다. 키는 저장소에 올리지 않습니다. 서버에 직접 접속할 수 없는 환경에서는 다음과 같이 **단일 종목** CSV로 실행할 수 있습니다.

```bash
python -m research.pre500 --input-csv data/my_stock_kiwoom.csv \
    --output output/offline_pre500.csv
```

CSV에는 `date,open,high,low,close,volume,trading_value`가 필수이며 `personal,foreign,institution`은 선택입니다. `date`는 거래일, 금액 단위는 원(KRW)입니다.

## 결과 해석

- `is_500eok_event`: 그날 기존 500억봉 조건 충족 여부
- `value_ratio_5_vs_prior20`: D-4~D 평균 거래대금 / D-24~D-5 평균 거래대금
- `higher_lows_5v5`: 최근 5일 최저가가 이전 5일 최저가보다 높은지
- `*_net_5_krw`: 최근 5일 투자주체 순매수 합계 (누락 있으면 `NaN`)
- `future_event_in_horizon`: 현재일 **이후** 1~5거래일 500억봉 존재 여부 (미래 데이터가 불완전하면 `NaN`)
- `eligible`: 직전 20거래일에 500억봉이 없으며 충분한 과거·미래 데이터가 있는 평가 대상일
- `candidate_exploratory`: 거래대금 비율 1.5배 이상 + 저점 상승이라는 **임시 연구 가설**. 검증된 매수 신호가 아님

출력된 발생률은 종목·날짜 단위 빈도이며 여러 날짜가 하나의 500억봉을 중복 예측할 수 있습니다. **전체 종목(미급등 대조군), 시계열 분리/검증, 종목별 중복 이벤트 처리 및 거래비용을 포함한 백테스트**를 마치기 전에는 예측률이나 수익률로 해석하면 안 됩니다.

## 후속 단계 (미구현)

1. 키움 과거 수급 데이터의 조회 가능 기간 및 결측 비율 검증
2. `news_report` 과거 `signal_event`와 이벤트 정의·시장 범위 일치 여부 비교
3. 다종목/대조군 일괄 수집기, 캐시 및 호출 제한 관리
4. 독립된 데이터베이스 테이블과 실험 리포트, 시계열 구간 외 검증

운영 중인 `investor_chart` 차트·FastAPI 서버와 `prebuy_screener`는 이 연구로 수정되지 않습니다.

## 최종 목표: 지지점 후보 풀 내부의 상승 전조 레이더 (2026-10-21 추가)

**전체 상장 종목의 급등을 예측하지 않는다.** 기존 `prebuy_screener`의 지지점 인근 후보(예: `우선검토40`, `1차필터결과`)를 입력받아, 그 중 **1~5거래일 내 상승 전조가 강해지는 종목을 우선 관찰**한다.

입력은 일자별 후보 풀 스냅샷이다. 신규 연구 모듈은 기존 운영 스크리너/키움 API 서버/서비스 파일을 변경하거나 주문하지 않는다. 정량 점수는 설명용 초기 규칙이며 실전 검증 전 매수 기준으로 사용하지 않는다.

### 사용 예시

기존 선취매 스크리너 XLSX 파일을 가져온 뒤, Oracle 서버에서:

```bash
cd /home/ubuntu/apps/investor_chart
source .venv/bin/activate
python -m pip install "openpyxl>=3.1,<4"
python -m research.support_pool \
  --pool "/path/to/선취매_1차필터_최신.xlsx" \
  --sheet "1차필터결과" --asof 20261020 \
  --market KRX --limit 5 \
  --output output/support_pool_20261020.csv
```

실제 `우선검토40` 시트가 포함되어 있으면 `--sheet`를 생략할 때 해당 시트를 우선 선택한다. 연결된 Google Drive의 `선취매_지지수급_20261008.xlsx` 실파일 열은 확인했다. Oracle 서버에 존재하는 실제 실행 대상 파일도 동일한 스키마인지 실행 전 검증한다.

키움 호출 없이 개별 종목 과거 시세 CSV로 재현하려면 `--price-dir /path/to/csvs`를 지정한다. 그 폴더에는 `005930.csv`처럼 종목코드 이름의 파일이 있어야 한다. 각 파일 컬럼은 `date,open,high,low,close,volume,trading_value`, 선택적으로 `personal,foreign,institution`; 날짜는 ISO 날짜 또는 YYYYMMDD, 금액은 원화이다.

**호환 입력 컬럼:**
- 종목코드: `종목코드` / `stock_code` / `code` (필수)
- 종목명: `종목` / `종목명` / `stock_name`
- 지지 종류: `최우선지지선` / `지지선` / `support_type`
- 지지가격: `support_price` / `지지점가격` / `지지선가격` / `지지가격`
- 이격도: `support_distance_pct` / `지지점이격도(%)` / `최우선이격도(%)`

지지 가격이 주어지면 실제 종가 기준 이격도를 재계산한다. 지지 가격이 없고 스냅샷 이격도만 있으면 해당 값만 사용한다. 가격·이격도 모두 없으면 **지지선 회복 신호를 생성하지 않는다.** 지지점 근처인지 여부는 원본 스크리너가 결정하며, 이 레이더는 독립적인 수급·가격 변화 점검에 집중한다.

### 1차 선행 신호 (가설, 검증되지 않은 임계값)

| 신호 | 임시 기준 |
| --- | --- |
| 자금 증가 | 최근 5일 평균 거래대금 / 이전 20일 평균 ≥ 1.5 |
| 상승일 수요 우위 | 최근 10일 상승일 평균 거래대금 / 하락일 평균 ≥ 1.25 (각 2일 이상) |
| 저점 방어 | 최근 5일 최저가 > 이전 5일 최저가 |
| 기관·외국인 수급 | 양 주체 합산 5일 순매수 ≥ 동 기간 거래대금의 1% |
| 지지점 회복 | 지지가격이 존재할 때 최근 5일 터치 + 현재 지지가 위 + 과도한 이탈 없음 |

3개 이상: `집중관찰`, 2개: `관찰`; 최근 5일 +25% 초과나 당일 500억봉 발생 시 별도 분류한다. **점수는 확률이 아니고**, 수급 정보 결측은 0원으로 대체하지 않는다.

### 반드시 해야 할 후속 검증

1. 먼저 실제 서버에서 날짜별 후보 풀이 어떤 경로·시트·컬럼으로 보존되는지 확인한다. 과거 연구에 **오늘 생성된 후보 풀을 소급 적용하면 미래정보 누출**이 발생하므로, 각 날짜 당일 확정한 풀 스냅샷만 사용한다.
2. 같은 풀 안에서 전조 감지 종목과 미감지 종목의 1·3·5거래일 뒤 주가를 비교한다. 결과 지표는 **향후 5일 최고가 +5%/+10%, 종가 수익률, 최대 불리한 움직임(MAE), 500억봉 발생**으로 분리한다.
3. 실제 체결 가능한 익일 시가 진입, 수수료·슬리피지, 연속 신호 중복 제거와 시계열 구간 외 테스트를 수행한다.
4. 1~5일 내 상승 결과가 충분히 구분되는지 확인한 후 임계값을 조정한다. 검증 전 자동매매·투자 등급 적용은 금지한다.


### 확인된 2026-10-08 지지수급 실파일 입력 스키마

연결된 Drive의 `선취매_지지수급_20261008.xlsx`에서 확인한 열 이름:
`우선검토군`, `우선검토순위`, `우선검토점수`, `대표테마`,
`검토등급`, `기준일`, `종목코드`, `종목`, `시장`,
`지지개수`, `접촉지지`, **`최인접지지`**, **`최인접지지가격`**,
**`최인접이격도(%)`**. 입력 어댑터는 이 열을 우선하여 처리하고
`우선검토군=Y`인 종목만 남긴 후 `우선검토순위` 순으로 정렬한다.
기존 MA20/60/120/224뿐 아니라 `VLOW_YYYY-MM-DD` 지지 종류도 원형을 유지한다.
실제 2026-10-08 파일은 여러 시트로 구성되어 있으므로 분석 시 적합한 시트를
`--sheet "우선검토40"` 등으로 명시하거나 기본 선택을 확인한다.
이 파일은 실제 시세와 결합해 분석/수익률 검증한 적이 없으며, 존재하는 값은 **1차 결과**이다.

### 1·3·5거래일 과거 후보 풀 내 비교 (백테스트 실험)

날짜별 기록된 원본 `선취매_지지수급_YYYYMMDD.xlsx` 스냅샷을 로컬
`/path/to/archives`에 보관했다는 전제에서 다음을 실행한다.

```bash
python -m research.backtest_support \
  --snapshots-dir /path/to/archives \
  --market KRX --limit 5 \
  --output-dir output/support_replay_trial
```

이 명령은 기존 `investor_chart`의 키움 계정 인증을 **읽기 전용**으로 사용한다.
동일 종목의 가격을 메모리 내 캐시하여 중복 API 호출을 줄인다.
미리 키움 자료를 `005930.csv` 형식으로 저장했다면 네트워크 없이:

```bash
python -m research.backtest_support \
  --snapshots-dir /path/to/archives \
  --price-dir /path/to/kiwoom_csv \
  --output-dir output/support_replay_offline
```

- `observations.csv`: 당시 종목 풀·2차 신호·다음 거래일 시가 및 향후 1/3/5거래일 최대 상승률·종가 수익률·최대 불리한 움직임
- `summary.csv`: **해당 지지점 종목 풀 내부에서** 신호 등급별 +5%/+10% 최고가 도달률 및 평균 수익률
- 관측 구간이 모자란 경우 `matured=False`, 성공/실패 계산에서 제외
- 실제 매매 손익과 구별: 일중 최고가 도달률은 체결 가능성/호가/슬리피지 반영 전 통계
- 소급 생성된 종목 풀(해당 날짜 장마감 시점에 실제 존재하지 않았던 파일)을 적용하면 미래정보 누출 위험이 있음
- `--limit`은 API 호출량을 제어하는 샘플 실험용 옵션. 검증 시 전체 지지 후보에 적용하고 추후 거래비용·리밸런싱 룰을 추가할 것

**주의:** connected Drive에서 찾은 2026-10-08 스냅샷의 이후 수익률,
2026-10-21 오늘자 상승 전조 결과는 아직 산출하지 않았다.
로컬 GitHub Actions는 API 자격증명이 없는 합성 데이터에 대한 테스트만 수행한다.

## 첫 실서버 검증 (별도 작업 디렉터리)

GitHub 연구 브랜치를 `git worktree`로 별도 체크아웃하고 설치한 뒤, 해당 일자의
`선취매_지지수급_YYYYMMDD.xlsx` 파일 경로를 전달한다. 기존 차트 서비스와
운영 브랜치를 변경하지 않는다.

```bash
# 파일 구조·날짜 검증: 키움 API 미호출
VALIDATE_ONLY=1 bash scripts/run_pre500_trial.sh \
  /path/to/선취매_지지수급_20261008.xlsx

# 작은 실데이터 시험: 우선검토군 5개만
bash scripts/run_pre500_trial.sh \
  /path/to/선취매_지지수급_20261008.xlsx 5 KRX

# 검증 후 40개 전체
bash scripts/run_pre500_trial.sh \
  /path/to/선취매_지지수급_20261008.xlsx 40 KRX
```

스크립트는 파일명의 기준일과 엑셀의 `기준일`이 일치하는지 검사한다. **해당 날짜에
실제로 완성·사용 가능했던 시점의 스냅샷인지 별도로 확인**해야 한다.
오라클 서버에 키움 인증서·API 비밀값을 노출하거나 GitHub에 업로드하지 않는다.
생성 결과는 Git 제외 경로 `output/pre500_trial/`에 저장된다.
